# 한계와 미완료 항목

## 측정 한계
1. **PC 1대**: i5-9400F(6코어) / RAM 8 GB / GT 710 / Windows 11. 다른 장비에서는 측정하지 않았다. 절대값, 특히 UI 응답과 메모리 압박은 장비에 크게 좌우된다.
2. **반복 수**:
   - 분석기: 조건당 30표본(2블록)이지만 블록은 2개뿐이다. bootstrap 구간은 표본 내부 변동만 반영하고, 프로세스 간·날짜 간 변동은 반영하지 못한다.
   - UI: 조건당 독립 실행 3회다.
   - 통계적 유의성 검정은 하지 않았다.
3. **프로젝트 5개, 활성 파일 1개씩**:
   - 활성 파일은 "상대 import가 가장 많은 파일" 규칙으로 정했다. 프로젝트의 다른 파일에서는 결과가 다를 수 있다. 파일 전환 시나리오(18개 파일)가 이를 일부 보완한다.
   - excalidraw의 `App.tsx`는 매우 큰 파일이라 분석 자체의 비용이 크다.
4. **편집은 합성 편집**: 파일 끝에 유효한 함수를 추가하는 방식이다. 실제 편집(중간 수정, 타입 변경, import 추가)은 무효화 범위와 분석 비용이 다를 수 있다.
5. **의존성 설치 조건**: lockfile 그대로 `--ignore-scripts`로 설치했다. postinstall로 생성되는 타입이나 빌드 산출물(`dist`)이 없으므로, 일부 import가 해석되지 않을 수 있다. Program 크기와 결과가 개발자의 실제 환경과 다를 수 있다.
6. **실행 정책이 실행 도중 바뀌었다**([data/run-policy-changes.md](data/run-policy-changes.md)):
   - 분석기는 게이트 1,500 MB, UI는 1,000 MB에 실행 중 감시를 적용했다.
   - UI 제외 규칙은 **데이터를 본 뒤** 두 번 다듬었다(시간 측정 단계로 한정, RAM 부족과 페이징 분리). 원래의 실행 단위 플래그도 함께 보존했다.
   - 초기 hono UI 2회는 메모리 감시가 없던 때 측정했다.
7. **사라진 첫 실행**: 첫 전체 분석기 실행(`p11-main`, 106블록)은 원시 데이터를 잃었다. 블록 중앙값 로그만 참고 자료로 남겼고, 통계에는 쓰지 않았다. 최종 데이터는 프로젝트별 재실행에서 얻었다(excalidraw는 한 번 중단된 뒤 재개).
8. **실험 세션 환경**:
   - 실험 중 사용자의 다른 앱(브라우저 등)을 사용자 승인 아래 종료했다.
   - Claude Code 메모리 보호는 UI 측정에서만 해제했다.
   - 프로젝트마다 실행 시각과 가용 메모리가 다르다(각 `env-*.json`과 UI `memory-monitoring.csv`에 기록).
9. **UI 시간 정의**: 프레임 콜백 기준이다. 물리적 화면 표시는 측정하지 않았다. VS Code TypeScript 서버와의 경쟁이 섞여 있다.
10. **메모리 측정**:
    - 유지 힙은 강제 GC 전후 차이이며 결과 캐시를 포함한다.
    - OFF 조건에서도 일부 블록에 0이 아닌 값(최대 약 240 MB)이 나타났다. GC 시점 차이로 보이며 원인은 확인하지 않았다.
    - 텍스트 1자당 힙 바이트로 예산 도달 시 힙을 추정한 값은 외삽이다.

## 원인을 확인하지 못한 관찰
- query(대조) 편집에서 Adaptive가 Fixed 800보다 9.4 ms(+6%) 느렸다(두 블록 같은 방향).
- vite UI 첫 Generate에서 캐시 ON이 OFF보다 느렸다.
- hono UI에서 같은 조건 안의 실행 간 그래프 해시 차이(2단계). UI 하네스가 결과 전체가 아니라 해시만 저장해 비교할 수 없었다.

## 미완료 / 수행하지 않은 것
| 항목 | 상태 |
|---|---|
| 사용자 연구 | 수행하지 않음 |
| 다른 장비·OS 비교 | 수행하지 않음 |
| UI 측정 3개 프로젝트 이상 | 2개(hono, vite)만. excalidraw·typeorm UI는 메모리 제약으로 하지 않음 |
| `.json` 스크립트 종류 버그 수정 | 원인만 확인. 제품 수정은 별도 PR로 남김 |
| Adaptive 용량을 실제 Program 크기 기준으로 바꾸는 개선 | 제안만 함(제품 변경 없음) |
| 바이트 기반 메모리 상한 | 제안만 함 |

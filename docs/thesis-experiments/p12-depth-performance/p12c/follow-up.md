## Trigger analysis

**VERIFIED (code):** changing depth in `App.tsx` resets the graph and immediately posts a new analysis request when a root or active file exists; it is not merely `setGraphDepth`. Generate posts `selectWorkspaceFile` when a root file exists. `selectWorkspaceFile` opens and shows the editor, then calls `postAnalysis`. Active-editor change schedules auto analysis with zero delay if the graph-root policy allows and no suppression/debug condition applies. Active-document changes schedule after 350 ms; save schedules immediately. Debug start clears the pending timer, but does not cancel a running analysis. The select-file path itself does not call the suppression helper. Each started active analysis advances generation and sequence. Stale detection occurs after `analyzeWorkspaceWithDepth` and payload preparation: discarding a stale result does **not** stop CPU or release the running analysis early. Expansions have their own generation checks.

**VERIFIED (fixture UI):** the preparation auto request and depth-change select-file request overlapped; the former finished Depth and was then dropped stale. The later manual Generate was a cache hit. Another auto request began after the manual host post but before the manual two-frame acknowledgement. The harness now waits for recorded preparation requests to finish and a quiet period, and reports intervening requests; it cannot prevent a new editor event generated by Generate itself. Treat timings with such intervening requests as contaminated.

**INFERRED:** reopening/showing the editor during select-file can lead to a subsequent active-editor event and auto scheduling. This is consistent with the code and fixture trace, but the P12-C1 JSONL contains neither the underlying editor event nor suppression state, so its exact trigger is unverified. Overlap is permitted by current implementation; whether it is intended product policy or a defect requires a separate decision. A separate PR could evaluate coalescing/superseding work, suppression of self-induced editor changes, or cooperative cancellation at safe traversal boundaries. Each option requires tests for edits, debug, and stale graph correctness; no policy is changed here.

## Fit: what the existing evidence shows

For E5C Single expanded, both ON and OFF stored 67 React Flow nodes / 122 edges, same 581 ? 494 CSS px pane, post-Fit viewport x=?739.1, y=161, zoom=0.1 and measured node bounds x=0..20592, y=0..1720. To fit the width even with **zero padding**, zoom must be at most `581 / 20592 = 0.02821484`. The product component sets `minZoom=0.1`; hence complete horizontal containment at that pane size and recorded layout is mathematically impossible. The actual projected extent was x=?739.1..1320.1. The file's `fitGraphView` calls `fitView({padding:0.12, duration:400})`, so a padded fit requires an equal or smaller zoom than the zero-padding upper bound. These observations meet the explicit classification **FIT_CLAMPED_BY_MIN_ZOOM** for these recorded snapshots. The exact pre-clamp zoom requested by React Flow is not logged, and this does not attribute rendering cost to virtualization or prove a general defect in all viewports.

The E5C Single ON pilot waited 1100 ms after the Fit click before recording its snapshot; it did not sample the viewport during animation, so completed animation is **not directly verified**. The Single OFF diagnostic sampled identical node positions and dimensions four times, 250 ms apart, before its snapshot. This supports position stability at that point, but it did not record four identical viewport samples and cannot establish that the Fit animation itself had completed. The Multiple ON snapshot also has max no-padding zoom 0.02821484 and was clamped; its old harness did not include the later stability gate. The derivative calculations are reproducible from unchanged original `e5c-before.json` via [analyze-e5d-fit.cjs](analyze-e5d-fit.cjs): [Single ON](e5c-single-on-pilot-1/e5d-fit-analysis.json), [Single OFF](e5c-single-off-diagnostic-1/e5d-fit-analysis.json), [Multiple ON](e5c-multiple-on-pilot-1/e5d-fit-analysis.json).

## File re-expansion: evidence and unknowns

Both E5C Single attempts confirmed a collapse of the `alpha/a.ts` group. The following re-expansion verification failed. In the OFF raw debug log, after the file collapsed (event seq 41), the next recorded click was `canvas.node.click` on the **parent alpha folder** (seq 42), not a `canvas.file-group.select` for `alpha/a.ts`; no proof shows that the intended file header received the re-expansion click. The ON run similarly failed its DOM-based post-click check, but does not independently establish whether the model had transitioned while the target was unmounted. The previous harness chose a coordinate based on hit-testing and later sent a raw mouse click; layout or viewport motion could make that target stale, but the E5C logs lack a click-time hit-test and do not prove that cause. A product state-transition defect, offscreen button, virtualization unmount, and actual cause of the wrong target remain **UNVERIFIED**. Do not equate the failed harness with a confirmed product bug.

The E5D test-only harness attempts to wait for a stable hit point, uses Playwright locator actionability for the same group ID, and captures trusted click target, group ID, button title, DOM presence, measured rectangle, center hit, animation count and model collapsed state on failure. It then requires same-group transition and graph/topology restoration. These proposed changes have **not been exercised end to end** because of preflight; they are not claimed to fix the race.

## Separate performance gate

The new [p13-p12e5d.spec.ts](p13-p12e5d.spec.ts) keeps Fit classification and records its before/after viewport and four matching 150 ms viewport samples as an observation of stability; Fit clipping alone does not invalidate an interaction sample. The test still rejects missing bounds, graph hash mismatch, selection/Inspector mismatch, group restoration failure and incomplete interaction phases. A pan moves along the same scripted path with 280 CSS px intermediate displacement and stores viewport samples; [compare-e5d.cjs](compare-e5d.cjs) separately requires equal logical and React Flow counts, IDs, group state, starting viewport and pane, a ?250 px observed pan, matched sampled viewport path and duration within 20%. A separate manifest comparison is still required. Recorded rAF times are callback intervals, not physical FPS, display paint or INP. DOM attach/detach event counts are not necessarily React mounts. Test-only measurement overhead is not isolated.

[run-e5d-pair.ps1](run-e5d-pair.ps1) alternates ON/OFF, stops a pair on invalidity and requires the first valid ON manifest/interaction reference. [test-e5d.cjs](test-e5d.cjs) passes six offline gate checks, including that a clamped Fit alone does not reject an otherwise comparable synthetic interaction and that mismatched viewport, pan, group state or invalid phases are rejected. Four E5C state-gate and four manifest tests also pass. These checks validate the gate logic against manipulated recorded data; they do not validate the new Playwright interactions on a live Webview. Single expanded ON/OFF repeated samples, decomposition of React commits, and all Multiple expanded comparisons remain **UNVERIFIED**.

# Request ownership follow-up

The Webview assigns a `web-` UUID to each manual Active or Expansion request regardless of whether P12-C profiling is enabled. The existing `profileRequestId` wire field carries the same ID to avoid introducing a second diagnostic ID. Host sequence/generation still order actual active and expansion work. Selection reserves a host sequence before opening a document. `analysisLifecycle` reports running, completed, cancelled, failed or superseded; the Webview's local pending state represents requested. GraphPayload is unchanged.

The Webview records the current loading owner and latest user Active ID. A terminal event only clears its own owner; a different user request's result cannot replace the latest user graph. Automatic results are ordered against the user's host sequence, including while the user request is pending. A stale error notice is ignored. Trace exit sends `cancelAnalysis` for a pending user request, releases its loading owner and rejects a later result. A debug start invalidates pending file selection and cooperatively cancels active work at the next safe boundary. Program creation remains non-interruptible.

The shared ownership predicates have deterministic tests for delayed A completion after B, B failure, cancellation without a successor, independent expansion, and automatic result ordering. `SelectionOrder` tests delayed open/show ordering. These are not full React/Host end-to-end state-machine tests. They do not demonstrate every UI interleaving, actual editor activation ordering, cancellation/failure notice delivery under VS Code shutdown, or debug-session start/end. The instrumentation-off full UI path and a complete policy-on/off graph comparison remain unverified.

The current build passed isolated P14 fixture Generate, Inspector, Dataflow, Trace on/off and request-correlated Webview smoke with profiling enabled. The [event log](lifecycle-ui.jsonl) and [harness output](lifecycle-ui.txt) preserve the run: five request begins, one cancellation, two Depth completions, four posts, and zero suppressed or dropped events. A separate [profiling-off smoke](lifecycle-off-ui.txt) verified a `web-` result ID without the profiling meta tag. The enabled run sampled 2,287 MiB before launch and a minimum 861 MiB after launch; the off run sampled 2,301 and 842 MiB. The one-second sampler does not observe the launch interval. Neither smoke compares the full graph against a policy-off build. Runtime Debug, delayed actual editor operations, rapid Depth/Generate, and failure injection require further real-VS-Code testing. Do not interpret the existing two-animation-frame diagnostic as physical paint. P12-C2's Vite D2 experiment remains out of scope. Keep PR #33 Draft until the remaining core UI races are exercised.

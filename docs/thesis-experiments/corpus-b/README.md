## 3. 파일 선정 규칙 (`corpus-b-selection/2`)

[select-files.mjs](../tools/corpus-b/select-files.mjs)가 다음 순서로 판정한다. 첫 번째로 해당하는 사유를 기록한다.

| 순서 | 사유 | 규칙 |
|---|---|---|
| 1 | `OUTSIDE_SRC_ROOT` | srcRoot 밖 |
| 2 | `NOT_TS_SOURCE` | `.ts`/`.tsx`가 아니거나 `.d.ts` |
| 3 | `TEST_OR_FIXTURE` | 경로나 이름이 test·spec·e2e·mock·fixture·stories·seed 등 |
| 4 | `GENERATED` | 머리 주석에 generated·autogenerated 표시 |
| 5 | `NO_FRAMEWORK_IMPORT` | 그 프레임워크 패키지를 import하지 않음 |
| 6 | `REEXPORT_ONLY` | 최상위 문장이 모두 import 선언이거나 `export ... from "m"`(TypeScript parser로 판정) |
| 7 | `TOO_SMALL` / `TOO_LARGE` | 코드 줄(빈 줄·주석 제외)이 10 미만 / 120 초과 |

- 남은 파일(eligible)을 경로순으로 정렬하고, EXP-01과 같은 `seededShuffle`(lib.mjs)에 프레임워크별 seed를 넣어 섞는다. 앞의 5개를 고른다.
- 이 선정은 MANIFEST 고정 후 바꾸지 않는다. Cogic 결과를 본 뒤에도 바꾸지 않는다.
- 판정 기록: React `apps/react-vite/src/types/api.ts`는 `GENERATED`로 제외되었다.
  - upstream이 직접 작성한 파일이지만 첫 줄에 "let's imagine this file is autogenerated from the backend"라고 적혀 있다.
  - 정해 둔 텍스트 규칙을 그대로 적용했다. 규칙은 바꾸지 않았다.
- 제외 사유별 개수

| 프레임워크 | NO_FRAMEWORK_IMPORT | TEST_OR_FIXTURE | NOT_TS_SOURCE | TOO_LARGE | TOO_SMALL | GENERATED | REEXPORT_ONLY |
|---|---|---|---|---|---|---|---|
| React | 64 | 37 | 3 | 6 | 1 | 1 | 0 |
| Vue | 10 | 27 | 27 | 1 | 1 | 0 | 0 |
| Express | 9 | 6 | 0 | 0 | 0 | 0 | 0 |
| NestJS | 47 | 13 | 31 | 6 | 11 | 0 | 0 |

### 3.1 선정 도구 수정 이력 (selection/1 → selection/2)

- 결함: selection/1의 `REEXPORT_ONLY`는 `;`와 줄바꿈 정규식으로 문장을 나눴다.
  - 세미콜론이 없는 파일에서는 마지막 import 문이 그 뒤 코드까지 한 문장으로 묶였다.
  - 그래서 Vue `src/main.ts`(앱 시작 코드 12줄)가 re-export 파일로 잘못 제외되었다.
- 발견 시점: 문서 작성 중 제외 목록을 점검하다 발견했다. MANIFEST 고정 전이고, Cogic을 이 코퍼스에 한 번도 실행하지 않은 상태였다.
- 조치
  - 선언한 규칙("re-export만 있는 파일")을 TypeScript parser로 구현했다(selection/2).
  - 같은 seed로 다시 추첨했다.
- 영향
  - React·Express·NestJS: 제외 판정, eligible, 선정이 모두 그대로다. 다시 빌드한 15개 사례도 바이트 단위로 같다.
  - Vue: eligible이 6개에서 7개로 바뀌었다. 선정은 다음과 같이 바뀌었다.
    - `src/main.ts` 추가 → 새 사례 bv01-main
    - `src/composable/use-tags.ts` 제외 → selection/1의 bv01-use-tags
  - Vue의 나머지 4개 파일은 그대로다. 추첨 순서가 바뀌어 사례 번호만 달라졌다.
    - use-async: bv05 → bv04
    - use-favorite-article: bv04 → bv05
    - 이 두 사례의 GT는 caseId 외에 같다.
- 판단 근거
  - 선언한 규칙과 실제로 적용한 규칙이 다르면, 그 표본은 선언한 절차를 따른 표본이 아니다.
  - 수정은 Cogic 결과와 관계가 없다. 수정 결과는 고정한 seed로 기계적으로 정해진다.
- selection/1의 선정 결과와 bv01-use-tags GT는 저장소에 넣지 않았다. 이 기록과 이전 수치로 대신한다.
  - selection/1 기준 합계: determinate 202, supported 81

### 3.2 같은 시점의 패턴 분류 정정

- 정정 내용: 초안 도구가 JSX 호출과 import 함수 호출의 패턴을 owner 위치보다 대상 형태로 먼저 정했다. 이를 [ANNOTATION_ADDENDUM.md](ANNOTATION_ADDENDUM.md) A4의 순서(owner 위치 우선, EXP-01 e03·h03 선례)로 고쳤다.
- 바뀐 패턴

| 사례 | 바뀐 관계 |
|---|---|
| br02, br05 | `FieldWrapper` JSX: CALL-JSX-IMPORT → CALL-IN-ANON-CALLBACK |
| br03 | `enableMocking()`: CALL-IMPORT-NAMED → CALL-TOPLEVEL |
| br03 | `App` JSX: CALL-JSX-IMPORT → CALL-IN-ANON-CALLBACK |
| bv01-main | 최상위 default import 호출 2개: CALL-TOPLEVEL |

- 영향: 바뀐 패턴은 모두 supported다. 그래서 관계·지원 분류·결정성은 바뀌지 않고, 패턴별 분해 표만 바뀐다.

## 6. 분석 환경

- TypeScript 5.9.3(저장소 `npm ci`). 외부 의존성은 설치하지 않는다.
- tsconfig는 upstream tsconfig에서 다음만 바꾼다([build-cases.mjs](../tools/corpus-b/build-cases.mjs) `deriveCompilerOptions`).
  - `types: []`, `skipLibCheck: true`, `noEmit: true`. `include`는 사례 안의 `.ts`/`.tsx`.
  - Express·NestJS는 `lib`을 DOM 없이 지정한다(Express `ESNext`, NestJS `ES2021`). untyped `Request`·`Response`가 DOM 전역 타입으로 해석되는 것을 막기 위해서다.
  - `paths`·`baseUrl`·`jsx` 등 모듈 해석 설정은 유지한다.
- 외부 패키지가 untyped이므로 TypeScript 진단이 생긴다. validator는 이를 오류로 보고하지만 GT 오류가 아니다. `validate.mjs`가 이를 `environmentDiagnostics`로 분리한다.
  - 사례별 진단 수: br03 706, bn03 209, bn01 79, br01 62, bn02 59, be01·be02·be05 각 53, bn05 38, br05 29, br02 28, br04 12, be04 10, bv02·bv05 각 7, bv01·bv04 각 5, be03 3, bn04 2, bv03 1
  - 주요 코드: 7026(JSX intrinsic 타입 없음), 2709·2694(untyped 모듈의 타입 사용), 7006·7031(implicit any 파라미터), 2591(Node 전역), 2347(untyped 호출의 타입 인자)
  - 이 환경 때문에 framework API의 대상 노드가 없다. 처리 방법은 [ANNOTATION_ADDENDUM.md](ANNOTATION_ADDENDUM.md) A1–A2에 있다.

## 8. 작성 방법과 독립성

1. [annotate-assist.mjs](../tools/corpus-b/annotate-assist.mjs)가 TypeScript checker로 지침 §2–§5에 따른 초안을 만든다.
2. 사례마다 원문과 지침을 대조해 검토하고, 결정을 [review/](review/)`<caseId>.mjs`에 코드로 남긴다(패턴 수정, 삭제·추가, 앵커, note).
3. [make-gt.mjs](../tools/corpus-b/make-gt.mjs)가 "초안 + 검토 결정"으로 `expected.json`을 다시 만든다. 이 과정은 결정적이다.

- Cogic analyzer를 이 코퍼스에 실행하지 않았다. 초안 도구는 analyzer 코드를 import하지 않는다.
- 작성자는 analyzer 구현을 읽은 적이 있다. 그래서 사람 검토 전에는 결과를 확정 수치로 쓰지 않는다.
- 애매한 관계는 지원 범위에 넣지 않고 indeterminate나 ambiguous 패턴으로 두었다.

## 10. 재현

```sh
# 저장소 checkout (각 SHA)
git clone https://github.com/alan2207/bulletproof-react <src>/react   && git -C <src>/react   checkout 9506629ed003a561c6627735480cce4994244bb4
git clone https://github.com/mutoe/vue3-realworld-example-app <src>/vue && git -C <src>/vue checkout 741c215ef0f674f90fcb03c5493a1b3a3a7f1b03
git clone https://github.com/edwinhern/express-typescript <src>/express && git -C <src>/express checkout 983fa0413659cd921c5754b00f7817903eb91364
git clone https://github.com/brocoders/nestjs-boilerplate <src>/nest  && git -C <src>/nest  checkout 9620f159eefe38f47747d02ab162852367c5472c

T=docs/thesis-experiments/tools/corpus-b
node $T/select-files.mjs --src <src> --json <out>/selection.json   # corpus-b/selection.json과 비교
node $T/build-cases.mjs --src <src> --selection <out>/selection.json --out <empty dir>  # 사례 폴더 생성(덮어쓰기 거부). expected.json 외에는 fixtures와 같아야 한다
node $T/make-gt.mjs                                               # 초안 + review/로 expected.json 재생성
node $T/validate.mjs --json <out>/validation.json
node $T/audit.mjs --src <src> --json <out>/audit.json
node $T/manifest.mjs --check                                      # 고정 해시 확인
```

- `make-gt.mjs`를 다시 실행해도 `expected.json`이 바뀌지 않아야 한다. `manifest.mjs --check`로 확인한다.
- checkout은 저장소에 넣지 않았다. 사례 폴더에는 선정 파일과 import closure만 있다.
- Windows 주의: 저장소 안 경로가 최대 155자다(NestJS 사례). 경로 260자 제한에 걸리면 clone 전에 `git config --global core.longpaths true`를 설정하거나 짧은 경로에 clone한다. 새 clone에서 `manifest.mjs --check`와 upstream 해시 449개가 모두 일치함을 확인했다.

## 11. MANIFEST

- `MANIFEST.json`은 다음 파일의 SHA-256(줄바꿈 LF 정규화)을 기록한다.
  - `corpus-b/fixtures/**`
  - `corpus-b/review/**`
  - `corpus-b/selection.json`
  - `tools/corpus-b/**`
- `manifest.mjs --write`는 파일이 이미 있으면 거부한다. 사람 검토로 GT가 바뀌면 새 manifest 파일을 만들고 기존 파일은 남긴다([EVALUATION_PROTOCOL.md](EVALUATION_PROTOCOL.md)).

# 06. 그래프 조작 성능 (Pan·Zoom·그룹 펼침·접기·선택)

**채택 버전의 조작 성능**: 채택 버전(`e753f5e`)의 웹뷰 코드는 P4(`9126f35`)와 같으므로, 아래 P8-F Baseline 측정이 채택 버전의 조작 성능이다. 이 단계에서 조작 성능을 개선한 코드는 채택되지 않았다([07](07-rejected-optimizations.md)).

## 1. 대규모 그래프 가시성 진단 (P8-A)
1,000·2,000파일에서 편집 결과가 화면에 보이지 않던 현상을 원인별로 분리했다.

| 상태 | 1,000파일 | 2,000파일 |
|---|---|---|
| A. 분석 데이터에 새 노드 존재 | 예(편집 후 1.2초) | 예(3.6초) |
| B. 그래프 DOM에 존재(편집 직후·Fit 후) | 아니오 | 아니오 |
| B/C. 캔버스를 실제로 끌어 이동한 뒤 DOM·뷰포트 | 예(1회 이동) | 예(2회 이동) |

- 원인: Fit이 `minZoom=0.1`에 고정되어 그래프 전체가 화면에 들어가지 않는다. 활성 파일 그룹이 화면 밖에 남고, React Flow `onlyRenderVisibleElements` 때문에 DOM에서도 빠진다. **데이터 누락이나 갱신 결함이 아니라 기본 가시성 제한**이다.
- 가설별 판정: 접힌 그룹 안(아니오, 활성 그룹은 펼쳐짐), 뷰포트 밖(예, 주원인), 필터·Root(아니오), React 상태 미반영(아니오), 비동기 지연(아니오), 하네스 판정 오류(부분적으로 예: 이전 스펙이 "Fit 후 DOM에 있으면 보임"으로 판정).

## 2. 측정 방법 (P8-F)
- 분석과 Generate가 끝나고 그래프가 2초 동안 안정된 뒤에만 측정했다(정적 분석 시간 제외).
- 조작마다 측정 구간 밖에서 Fit으로 시작 뷰를 통일했고, 경로·속도·횟수는 고정했다.
  - pan: (+100, +200) ↔ (−100, −200) px 드래그 3왕복, 30 step
  - zoom: 휠 3회 확대 후 3회 축소
  - 그룹 토글: hit-test 가능한 그룹 머리글 2회 클릭
  - 노드 선택: `runEntry()` 클릭
  - 노드 드래그: 그룹 머리글을 드래그
- 상태: 기본(접힘) / 확장(hit-test 가능한 접힌 그룹을 최대 10개까지 펼침)
- 지표: 웹뷰 rAF 콜백 간격(FPS, 프레임 시간 중앙값·P95·P99, >33.3 ms·≥50 ms 비율), 입력 이벤트 → 다음 rAF 지연, Electron `getAppMetrics` CPU.
- 정확성: pan 후 원위치 복귀, zoom 후 배율 복귀, 드래그 시 노드 위치 불변, 그룹 접힘 상태 전환, Inspector 선택 표시. **정확성 검증에 실패한 조작은 통계에서 뺐다.**
- 노드 드래그는 Cogic이 지원하지 않는다(`nodesDraggable={false}`, 드래그하면 캔버스가 이동). "지원하지 않음"을 확인하는 검증으로만 측정했다.
- 규모마다 독립 실행 3회, 규모 순서를 회차마다 바꿨다.

## 3. 결과 (Baseline `9126f35` = 채택 버전 웹뷰, 실행 3회 중앙값)
≥50 ms 프레임 비율 / 프레임 시간 P95(ms). 전체 표는 [data/p8/p8f-interaction-ops.csv](data/p8/p8f-interaction-ops.csv)에 있다.

| 조작 | 100 | 500 | 1,000 | 2,000 |
|---|---|---|---|---|
| pan(접힘) | 0% / 12.9 | 0% / 14.7 | 0.2% / 20.6 | 9.2% / 81.1 |
| pan(확장 10그룹) | 1.0% / 12.6 | 7.4% / 67.6 | 22.2% / 137.8 | 21.6% / 112.3 |
| zoom(접힘) | 0.7% / 9.6 | 0% / 16.7 | 0% / 12.9 | 5.6% / 50.2 |
| 그룹 펼침·접기(접힘) | 2.7% / 29.9 | 6.1% / 54.8 | **26.2% / 253.5** | **29.6% / 1,037.5** |
| 노드 선택 | 13.8% / 100.2 | 11.5% / 111.8 | 11.5% / 79.2 | 13.0% / 104.3 |

- idle 상태는 모든 규모에서 120 fps(이 환경의 rAF 상한), ≥50 ms 0%였다.
- 1,000파일 이상 그룹 펼침·접기에서 입력 → 다음 rAF 지연 P95는 270 ms(1,000), 1,015 ms(2,000)였다.
- 노드 선택의 작은 규모 긴 프레임은 Chromium 추적에서 대응하는 긴 작업이 없어 **원인을 확인하지 못했다**(Playwright 클릭 처리의 영향 가능성, 미검증).

## 4. 병목 분석
| 근거 | 내용 |
|---|---|
| 추적(P8) | 심하게 끊기는 구간(1,000파일 그룹 펼침·접기, 확장 pan)에서 GPU 프로세스 메인 스레드가 91–94% 점유됐다. 웹뷰 메인 스레드는 13–18%였다. 렌더러 래스터 기록은 작았고 체커보드는 거의 없었다 |
| 기각 | 애니메이션 엣지(DOM에 0개), backdrop-filter·blur(사용 안 함) |
| 단일 요인 진단 빌드(P9, 1,000파일, 2회씩) | **뷰포트 가상화 해제**만 확장 pan을 크게 개선(55.5 → 101.4 fps, ≥50 ms 6.7 → 0.7%). 그림자 제거는 효과 없음. 그룹 펼침 확대 애니메이션 제거는 접힘 상태 토글만 일부 개선 |
| 결론 | 확장 상태 pan·zoom·선택의 끊김에는 React Flow 가상화(화면에 들어오고 나가는 노드의 반복 마운트)가 크게 기여한다. 반면 그룹 펼침·접기는 어떤 단일 변경으로도 해결되지 않았다. 가상화를 끄면 펼침·접기가 더 느려지는 상충이 있다([07](07-rejected-optimizations.md)) |

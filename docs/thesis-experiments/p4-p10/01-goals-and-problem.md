# 01. 연구 목표와 핵심 문제

## 연구 목표
Cogic은 TypeScript/JavaScript 코드의 호출·데이터 전달·참조 관계를 VS Code 안의 그래프로 보여 주는 확장이다. P4–P10의 목표는 다음 세 가지였다.

1. **탐색 흐름의 정확성**: 그래프 탐색 중 디버깅을 시작·진행·종료해도 시작점, 선택 노드, Root 설정이 유지되는지 실제 VS Code UI에서 검증한다.
2. **응답 성능의 객관화**: 정적 분석 시간과 사용자가 보는 그래프 응답·조작 시간을 구분해 측정하고, 측정 기준(프레임 콜백, Chromium presentation feedback)을 명확히 한다.
3. **확인된 병목만 개선**: 측정 근거가 있는 병목만 고치고, 기능 회귀와 다른 조작의 성능 악화가 없는 변경만 채택한다.

## 핵심 문제 정의

| 문제 | 증상 | 확인 단계 |
|---|---|---|
| 디버깅 중 탐색 상태 손실 | 중단점에서 멈추면 그래프가 다른 파일 중심으로 다시 그려져 시작점(`runDemo`)과 선택이 사라짐. File Root에서 프레임이 매핑되지 않음. Folder Root 직접 설정이 해제됨 | P3 → P4에서 수정, P5에서 재검증 |
| 대규모 프로젝트 캐시 역효과 | 1,000파일 이상에서 SourceFile 캐시 적중률 0%, 캐시를 켜면 편집 분석이 더 느림 | P6(측정) → P9(원인·개선) → P10(채택) |
| 대규모 그래프 편집 결과 가시성 | 1,000·2,000파일에서 편집이 반영되었는데도 화면에서 보이지 않음 | P8-A(원인: Fit 최소 배율과 가상화) — 개선안은 불채택([07](07-rejected-optimizations.md)) |
| 그래프 조작 끊김 | 1,000파일 이상에서 그룹 펼침·접기, 확장 상태 pan이 끊김 | P8-F(측정) → P9/P10(원인 분리, 개선안 불채택) |

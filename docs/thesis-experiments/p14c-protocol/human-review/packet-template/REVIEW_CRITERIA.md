# 관계 종류별 판정 기준

[RELATION_DEFINITIONS.md](RELATION_DEFINITIONS.md)의 정의가 우선한다. 이 문서는 정의를 적용할 때 확인할 질문을 정리한 것이다. 둘이 어긋나 보이면 정의를 따르고 `ambiguities.csv`에 적는다.

## 공통

| 질문 | 예이면 | 아니면 |
|---|---|---|
| 양 끝이 §2의 노드인가(지역 변수·파라미터·속성·모듈 namespace는 노드가 아니다) | 다음 질문 | 관계로 적지 않는다. 호출 지점이면 `sites.csv`에 `no-node-target` |
| owner가 §3의 규칙(가장 가까운 이름 있는 선언, 이름 없는 콜백은 투명, 최상위는 파일)에 맞는가 | 다음 질문 | owner를 다시 정한다 |
| 소스만 보고 대상이 **하나로** 정해지는가 | `determinate` | `indeterminate` (후보 열거 또는 `unbounded`) |

"하나로 정해지는가"는 사람이 소스와 타입만으로 답할 수 있는지를 묻는다. 도구가 해석하기 어렵다는 것은 기준이 아니다.

## `calls`

- 호출식의 대상이 노드인 함수·메서드인가. 메서드면 수신 객체의 **정적 타입**으로 선언을 찾는다.
- 오버로드: 실제로 선택되는 선언이 여럿 중 무엇인지 적고, 판단이 어려우면 `ambiguities.csv`에 후보를 적는다.
- `super(...)`, 태그된 템플릿, 데코레이터 호출, JSX 컴포넌트 사용은 정의(§4.1)를 확인한다.

## `constructs`

- `new X(...)`의 `X`가 노드인 클래스인가. 같은 지점에서 `calls`를 함께 적지 않는다.

## `references`

- 호출·생성·JSX 태그 대상이 **아닌** 위치에서 노드를 이름으로 쓰는가(값으로 넘기기, 타입 위치, 상속·구현 절).
- 제외 위치(선언 이름, import/export 지정자, 지역 선언이 가리는 경우)를 확인한다(§4.3).
- 같은 owner·대상 쌍에 `calls`와 `references`가 둘 다 있을 수 있다(예: 한 번은 호출, 한 번은 값으로 전달). 각각 적는다.

## `updates`

- framework 상태(React setter·dispatch, Vue ref·reactive 쓰기)를 **바꾸는** 지점인가(§4.4, §5). 읽기만 하면 `updates`가 아니다(`references`일 수 있다).

## `dataflow`

- 노드인 함수에 인자로 값이 들어가는가. 인자 위치(0부터)와 받는 파라미터를 적는다. 나머지 파라미터(`...args`)·구조분해는 정의(§4.5)를 확인한다.

## `owner` (framework)

- 해당 framework 모듈에서 가져온 API가 실행하거나 관리하는 콜백·상태·route가 있는가(§5). 사용자 정의 hook이나 같은 이름의 지역 함수는 아니다.

## 확신도

| 값 | 쓰는 경우 |
|---|---|
| `high` | 정의를 그대로 적용했고 다른 해석이 떠오르지 않는다 |
| `medium` | 다른 해석이 가능하지만 정의상 이쪽이 맞다고 본다. `note` 필수 |
| `low` | 정의로 결정하기 어렵다. `note`와 `ambiguities.csv` 필수 |

## 정의된 관계에 맞지 않는 것

이벤트 이름 문자열로의 연결, 의존성 주입 토큰, 동적 `import()`의 모듈 같은 연결은 관계로 억지로 넣지 않는다. 코드에서 의미가 있다고 보면 `outside-definitions.csv`에 적는다. 이 기록은 정답에 들어가지 않으며, 정의의 한계를 보고하는 데 쓴다.

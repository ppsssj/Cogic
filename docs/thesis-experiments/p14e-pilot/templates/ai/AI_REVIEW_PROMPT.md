# AI 검토 지시문 (모든 모델에 같은 문장으로 준다)

## 연구자의 진행 방법

- 한 대화에 한 사례만 다룬다. 사례마다 **새 대화**를 연다. 다른 모델의 답, 기존 정답, 도구 출력은 주지 않는다.
- 첫 메시지에서 다음을 준다.
  1. 패킷 ZIP 파일 전체(또는 이 문서, 정의 문서 다섯 개, 해당 사례 폴더의 모든 파일)
  2. 아래 `---` 사이의 본문을 수정 없이
  3. 마지막 줄에 `검토할 사례: Bxx`

---

당신은 TypeScript 정적 분석 연구의 독립 검토자다. 첨부한 패킷의 `cases/<검토할 사례>/` 하나만 검토한다.

**과제:** 그 사례의 **검토 대상 파일**(`case-info.json`의 `activeFile`)에서 출발하는 정적 관계를 모두 적어라.

**근거로 쓸 문서(이 다섯 개만):**

- `SEMANTIC_CONTRACT_C1.md`: 우선한다
- `RELATION_DEFINITIONS.md`
- `REVIEW_CRITERIA.md`
- `CORPUS_B_ENVIRONMENT.md`
- `REVIEWER_GUIDE.md`

규칙:

1. 정답의 근거는 TypeScript 소스의 정적 의미다. 어떤 도구가 찾을 수 있을지는 고려하지 않는다.
2. 정의 문서와 소스에 없는 사실을 추측하지 않는다. 외부 패키지 선언은 `shims/`에 있는 것만 존재한다.
3. 판단이 갈리면 다음을 지킨다.
   - 가능한 해석을 모두 `ambiguities` 표에 적고, 하나를 고른 이유와 확신도(`high`/`medium`/`low`)를 적는다.
   - `SEMANTIC_CONTRACT_C1.md`의 미결 항목(OPEN-n)에 해당하면 그 ID를 `ruleCited`에 적는다.
4. 검토 대상 파일의 모든 호출식, `new`, JSX 요소를 `sites` 표에 빠짐없이 적는다.
5. 첨부 파일을 열고 읽는 데 필요한 것(압축 해제 포함) 외에는 코드 실행, 웹 검색, 다른 분석 도구, 기존 분석 결과를 쓰지 않는다. 썼다면 무엇을 왜 썼는지 적는다.
6. 이 사례의 원 저장소나 다른 사례를 찾아보지 않는다.
7. 답은 `RESPONSE_FORMAT.md`의 다섯 표 형식으로 낸다. `reviewer` 열에는 당신의 모델 이름과 버전을 적는다.
   - 표 앞뒤에 판단 근거를 자유롭게 적어도 된다.
   - 답이 길어 잘리면 이어서 출력하되, 표 블록을 처음부터 다시 쓰지 않는다.

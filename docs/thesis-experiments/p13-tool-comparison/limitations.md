# 한계

## 측정 범위
1. **사용자 연구를 수행하지 않았다.** 사람의 이해 시간, 정확도, 생산성, 맥락 유지감은 측정하지 않았다. 조작 수는 스크립트에 정해진 경로의 클릭·단축키 수이며, 사람의 시행착오·스크롤·패닝·확대를 포함하지 않는다.
2. **과제 수가 적다.** 예제 1개(T1–T4)와 실제 프로젝트 과제 4개(hono 2, vite 2)다. 과제는 사전 등록 기준으로 골랐지만, 다른 코드 구조(데코레이터, 동적 호출, 콜백 체인, JS 프로젝트 등)에서는 결과가 다를 수 있다.
3. **실제 프로젝트의 디버그 연계(R4)는 측정하지 않았다**(사전 결정). Cogic의 디버그 프레임↔그래프 연계는 Stage A 예제에서만 확인했다.
4. **Context Graph는 평가하지 못했다.** Windows x64용 worker가 패키지에 없다. macOS arm64 장비에서는 실행하지 않았다. 이 결과는 Context Graph의 기능 부재를 뜻하지 않는다.
5. **반복 3회는 결정성 확인용이다.** 모든 분류와 조작 수가 3회 같았다. 통계적 검정은 하지 않았다.
6. **PC 1대, VS Code 1.147.0 한 버전**에서 측정했다. TFF와 Context Graph는 각 1개 버전만 측정했다.

## 절차와 판독
7. **스모크 후 절차 보완(A1–A6)**: 본 측정 전에 커밋했지만, 보완의 상당수가 Cogic 쪽이다(폴더 그룹 펼침, 캐시 기본값, 알림 회피 드래그, 멤버 행 판독, PARAM FLOW 판독). 공정성 판단은 [preregistration-stage-b-addendum.md](preregistration-stage-b-addendum.md)의 근거와 함께 보아야 한다. 같은 시점에 TFF 판독도 고쳤다(A5).
8. **판독 정정(C1–C3)**: 집계 단계에서 스펙의 판정 오류 3건을 정정했다. 원래 값을 함께 보존했다. 정정은 모두 기존 '성공' 또는 '미지원'을 '실행 실패'로 낮추는 방향이었다.
9. **화면 밖 노드**: Cogic은 판독 전에 Fit을 썼고(사전 등록, 미집계), TFF에는 같은 기능을 쓰지 않았다(TFF에는 Fit 버튼이 보이지 않음). 두 도구 모두 사람이 직접 캔버스를 옮겨 찾는 탐색은 측정하지 않았다. 사람이 패닝하면 V1·V2의 일부 실패 과제를 수행할 수 있을 가능성이 있다.
10. **Cogic V1·V2 R2 성공은 PARAM FLOW 기본 목록(처음 20개)에 해당 구간이 들어 있었기 때문이다.** 목표 노드를 선택하지 못한 상태였다. 다른 프로젝트나 파일에서는 목록에 들어가지 않을 수 있다.
11. **VS Code 인자 전달**은 기본 설정(inlay hint 꺼짐)에서 평가했다. 매개변수 이름 inlay hint를 켜면 호출 지점마다 매개변수 이름을 볼 수 있다. 다만 이 기능은 구간을 연결한 흐름 뷰가 아니다.
12. **자동화 실행 시간**에는 대기 시간이 들어 있다. Cogic Depth 2의 긴 Generate 시간(vite 4–6.5분)은 관찰값이며 원인은 분석하지 않았다.

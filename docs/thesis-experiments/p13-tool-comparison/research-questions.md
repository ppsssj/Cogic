# 연구 질문과 범위

| RQ | 질문 | 이 연구에서 답하는 방식 |
|---|---|---|
| RQ1 | Cogic은 VS Code 기본 기능과 코드 시각화 확장에 비해 어떤 코드 탐색 작업을 지원하는가? | 4개 도구에 같은 과제를 주고, 각 도구의 정상 조작 경로로 수행했을 때 UI에 실제로 나타난 결과를 분류한다([methodology.md](methodology.md)) |
| RQ2 | 정적 호출 관계, 인자 전달, 소스 이동, 런타임 디버깅을 연결하는 Cogic의 통합 탐색은 어떤 기능적 이점을 주는가? | 과제 T1–T4(R1–R3)별 분류, 스크립트 경로 기준 조작 수, 소스 이동 후 뷰·시작점·선택 유지, 디버그 프레임↔그래프 대응 |
| RQ3 | 이 기능이 실제 오픈소스 프로젝트에서도 재현되는가? | hono·vite의 실제 호출 경로 4개(사전 등록, 정답 고정)에서 같은 절차로 측정 |

## 하지 않는 것
- **사람의 이해 시간, 정확도, 생산성은 측정하지 않았다.** 사용자 연구도 수행하지 않았다. 조작 수는 정해진 스크립트 경로의 클릭·단축키 수이고, 자동화 실행 시간은 대기를 포함한 기록일 뿐이다.
- 성능 최적화는 이번 단계의 목표가 아니다.
- 도구의 우열을 하나의 점수로 합치지 않는다. 도구마다 설계 목적이 다르다. 예를 들어 Trace Function Flow는 함수 하나에서 시작하는 호출 추적, Context Graph는 전체 구조 그래프, VS Code는 범용 편집기 탐색을 목표로 한다. 그래서 과제별 지원 여부와 근거만 비교한다.
